# Replay 驱动的确定性导航脚本设计

状态：待用户审阅；本文件是接口与行为设计，不代表功能已实现或通过物理验证。

## 目标与选择

从成功 replay 中提取机器人操作站位与操作对象、环境的关系；在新场景自动选择合适站位并生成导航路径；用代码闭环处理加速、减速、停车、稳定等待和操作交接。正常路径不调用 GPT。同一算法覆盖任务，差异由场景绑定、关键阶段和允许接触等数据表达。

讨论过直接平移历史站位、历史关系加有限候选验证、在线联合优化导航与操作三种方式。用户明确要求 replay 分析与导航控制落成脚本。本设计推荐第二种：保留可解释先验，约束搜索预算，复用现有工作流；不实现大型联合优化器。

## 当前代码与缺口

- `workflow/planning.py:nominal_stance` 已有历史物体变换下的站位映射；`candidate_plan` 已有入口 IK、接近路径和底盘路径检查，但不能以此证明后续操作可行。
- `workflow/motion.py:DistanceVelocityProfile` 已有距离/速度反馈与命令加速度限制；它不保证实际机器人加速度。
- `workflow/parking.py` 已有停车响应拟合、严格适用范围检查、有界修正。
- `measured_approach` 可从实际姿态生成接近轨迹；保留其物理执行接口，不直接写入机器人状态。

## 三个脚本入口（拟新增，名称可由实现者调整）

1. `navigation extract --replay ... --bindings ... --out prior.json`：纯读入、离线提取，无物理步进。
2. `navigation plan --prior ... --scene ... --state ... --out plan.json`：几何/运动学规划，无物理步进。
3. `navigation execute --plan ... --experiment ...`：经现有实验合同校验后，使用现有 SONIC 工作流执行；执行之前重新校验计划适用范围和当前状态。

模块置于现有 workflow 下，CLI 只做参数与结果序列化。输出包含源文件哈希、坐标系、时间对齐、使用的阈值、每个候选淘汰原因、计划耗时与预算。

## 输入与提取

输入必须包括时间戳、实际 root 和关节状态、场景模型及对象位姿、任务对象绑定、已知操作阶段；手指命令与实测状态分开。已有 workflow 的 bindings/phases 优先使用。只有动作数组不足以可靠识别语义对象或任务成功，不猜测对象。

第一版允许使用现有元数据指定操作对象和阶段，不要求 GPT 每次标注。缺少阶段时，可以用接近距离、实测接触、末端速度、物体运动生成带置信度的候选阶段；歧义返回 needs_annotation，不自动将最长静止段认作操作站位。缺少成功证据的 replay 可分析但不得标记为成功先验。

在操作开始前寻找持续满足根部低速、低角速度与可用支撑证据的窗口，使用窗口统计值而非单帧确定参考站位，并保存离散程度及源帧。没有合适窗口的连续移动任务返回 unsupported_entry_pattern；同一导航模块适用于其可识别的入口，不代替接触后的移动控制。

提取对象到机器人平面变换、操作方向、机器人到可识别桌沿/表面边界的关系、表面高度、操作入口与关键末端目标。方向来源必须明确：物体有语义轴则用该轴；球形对象优先用支撑面法向/桌沿与成功接近方向，不能依赖任意物体 yaw。初版环境特征来自仿真模型绑定与几何，点云语义识别不在范围内。没有可靠桌沿时只使用对象关系及场景碰撞检查，并标明缺失约束。

bindings 对场景实体和语义轴进行声明；不在通用算法中按苹果/椅子/按钮名称分支。四个已有任务通过薄适配器读取各自元数据，无法映射时明确报错。

## 新场景的操作站位计算

以世界重力轴为竖直轴，使用任务参考系的 SE(2) 变换：新站位 = 新任务系 × 旧任务系逆 × 旧站位。高度变化进入手部目标与可达性检查，不能将底盘随桌面升高。环境并不随操作对象整体移动，因此所有碰撞和表面距离均在新场景重新计算。

先检查当前位置是否已满足操作条件；否则检查变换后的名义站位，再按固定顺序生成有上限的局部平移、转角候选。候选范围与步长是显式配置，不能由单次成功演示推断为可靠容差。随机规划器固定种子并设置迭代和耗时预算，记录种子；几何确定性不意味着物理轨迹逐位相同。

硬过滤包括：有效支撑面、身体及步态走廊余量、可达底盘路径、实测起始状态到操作入口的连续接近路径，以及完整已生成操作轨迹的有界采样检查。阶段边界、接触开始、最大伸展和首次抬起/按压/落座等关键目标必须包含；中间段按显式分辨率检查连续连接，超出预算返回 inconclusive，不能把几个独立 IK 成功当作连续轨迹证据。后续接触动力学仍需物理验证。

有意接触由阶段 contact_policy 指定；无元数据时不自行豁免碰撞。各任务输出同一格式的关键目标与接触策略。

可行候选排序采用明确的分级规则：满足最低可达/碰撞余量后，优先较短路径，再较少转向、较小先验偏离，最后稳定 ID 打破平局。不建立难解释的多参数打分器。目标是可操作站位集合中的一个点，不要求机械地追到历史坐标。

## 导航与速度控制

运行状态为 WALK → BRAKE → SETTLE → HANDOFF，异常进入有界 CORRECT 或 FAILED。是否步进、稳定时间、最大修正次数、最小进展量和总超时全部显式配置。

复用现有 DistanceVelocityProfile。每步读取实测位置、世界系平面速度、姿态和支撑状态；根据剩余路径、末端距离、转弯约束和制动响应更新速度目标。命令速率受加速度限制，yaw 同时受角速度/角加速度限制。接口转换明确记录 world/body 坐标，针对转向和坐标符号做测试。

停车响应采用已验证适用范围内的局部模型 p_stop = p + tau*v；模型记录速度范围、残差、机器人/控制器/物理配置身份。当前停车校准代码的严格 source/scope 检查不得直接放宽来声称跨任务复用。第一版沿用严格校验；不匹配时报告 needs_calibration 或使用明确标记、经单独验证的固定保守配置，不能静默借用模型。

速度包络中的 sqrt(2*a*d) 是控制设计，不是已验证物理制动保证。命令加速度与实测制动能力分别记录。弯道提前限速，终点才使用到达判据；不能在每个中间路点突然停车，也不能直线切过未检查障碍。停车预测误差加入余量。没有已验证参数时允许离线生成计划，阻止宣称可安全执行的自动运行。

到达后需要持续低速/低角速度、合适支撑、实际姿态可达、无禁止接触，才从实测状态重新生成操作桥接段。交接失败允许有限次修正；连续无进展直接返回明确原因。新场景中停止落点满足操作条件即可，不为缩小无意义坐标误差持续微调。

## 经验数据与研究解释

每次 extract/plan/execute 分别记录类型；纯规划失败不是物理失败。保存先验 ID、环境变化、候选理由、停车预测/实测误差、交接结果和最终操作结果，交给已实现的独立经验数据集收集器。不能把导航到位率当作任务成功率。

这是一条 replay 提取关系后生成新导航动作的链路。下游若访问或变换原始操作序列，仍标记 trajectory_retargeting，并记录 planner_access_to_original_actions；导航脚本本身不能证明全任务策略迁移。

## 实现与验证顺序

先完成离线提取、候选站位和可审计计划，然后接入已有速度/停车控制，最后接入四个任务。先使用冻结记录做只读分析与单元测试，不修改历史证据，不启动新物理实验。

测试覆盖已知刚体变换、球形物体 yaw 歧义、桌面高度变化、物体靠近桌沿、入口可达而后续不可达、禁止/允许接触、候选预算耗尽、转弯障碍、速度坐标转换、减速过冲、无进展修正、无效/过期校准与当前站位可用时跳过导航。适配四任务必须有真实记录格式夹具；不得用四份同构合成数据宣称已接通。

物理验收另行冻结 experiment.json，依用户规定使用指定运行时与真实控制模式。分别报告规划可行率、实际到位率、交接通过率、交接后的操作成功率、端到端成功率、耗时与 GPT 调用数。保留原导航和原轨迹方法为可区分基线；不能将去掉原 token 前缀的结果描述成只有导航参数变化。下一次正式历史 IK/mode0 与 SONIC 对比仍遵守指定十个位置条件。

验收界限：脚本可证明固定输入下的有界决策与审计完整性；位置泛化成功率与加减速物理可靠性需实测，不承诺所有任务必定成功。
