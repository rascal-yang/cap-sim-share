# 全任务经验数据集设计

状态：设计待用户确认，尚未实现。创建：2026-10-26T19:52:50+08:00。

## 目标与已确认范围

用户选择：独立建立一个覆盖所有任务的经验数据集，每次尝试都可保存；分开记录编排经验和控制执行经验，供 GPT 快速检索；采用“结构化记录＋简短经验摘要＋原始证据引用”。目标是减少重复探索，并通过对照判断是否提高成功率。历史苹果导航抓取的位置迁移是后续目标之一，不代表本设计只覆盖苹果。

以下存储、检索和接入细节是设计建议，待确认。本设计不启动新物理实验、不调用外部模型、不修改冻结实验，也不宣称检索已经有效。

## Approaches：已讨论方案

1. 每次尝试一篇文档：易读，但筛选、统计与去重困难。
2. 仅结构化记录：易校验和查询，但决策背景不易理解。
3. 结构化记录、摘要、证据引用并存：兼顾检索、解释和追溯，需统一模式与导入适配器。

用户已选择第三种。Skill 负责“何时检索、如何使用证据”；经验正文进入独立数据集，不把每个案例制成一个 Codex 工作流 skill。

## 与现有项目的关系

现有 augmentation/jobs.py 提供任务事件，generalization_benchmark.py 提供候选、重试、回溯和独立回放关联；各案例保存 result.json、experiment.json、控制日志及状态轨迹。src 下的通用 pipeline 和 humanoid_mimicgen/workflow 也是独立生产者，不能假定所有历史记录都具有相同结构。

新数据集是这些产物的派生索引。现有任务成功目录、训练导出索引和任务 skill 版本继续保持原含义。记录入库不表示物理成功，不表示可训练，不表示因果规律。数据集不能替代物理验收或赋予新的控制权限。

## 存储与版本

建议代码放在独立的 humanoid_mimicgen/experience_dataset/ 模块，实际数据默认位于工作区 experience-dataset/，CLI 支持显式路径。目录位置是默认建议，不依赖 cwd。模块不要依赖仿真初始化，也不复用旧 records.index_history 的兼容链接功能。

- records/<attempt_id>/<revision>/：规范 JSON、摘要 Markdown、证据清单。已发布 revision 不覆盖，修正生成新 revision 并说明原因。
- index.sqlite3：可重建的元数据与全文检索索引；索引损坏不影响规范记录。
- snapshots/：固定记录版本、哈希和检索配置的数据集快照。
- ingestion/：导入清单、解析失败、隔离条目、待补充与覆盖率统计。
- queries/：检索请求、返回 ID/版本、排序理由及实际提供给 GPT 的内容；排除密钥等凭据。

不复制全部 MP4/NPZ，仅引用源路径、文件哈希及必要的时间/数组范围。优先保存相对工作区定位信息及原路径。历史旧路径通过 experiments/_index/latest-migration.json 的映射解析，不改写原证据、不创建兼容链接。只有日期的旧 ID 保留原样，不能从 mtime 推断开始分钟。实际运行、规划、仿真、渲染起止与用时逐项记录，未知为 null 加原因。

attempt_id 基于稳定来源身份（源实验 ID、案例局部 ID、真实执行/决策事件 ID）生成，不能只用内容哈希；内容相同的两次真实执行仍是两条记录。同一次执行被多份汇总引用时只对应同一个 ID。历史歧义保留待核对，不能猜测合并。

## 记录单位与两类经验

顶层一次尝试包含共同背景及两类可缺省记录；一条尝试可以包含多个阶段和指令事件。实际执行、候选提议、验证回放、基础设施错误分别分类，不混算次数。

共同字段：schema_version、attempt_id、revision、producer、原实验完整 ID、task_id、机器人/手型、场景描述、对象几何与相对位姿、控制器/代码/模型版本及 provider 证据、初态引用、方法分类、原动作序列访问权限、时间、预算、证据可用性。

### 编排经验

每个决策事件记录 observation_before、问题描述、已记录的诊断、decision_origin（API/人工/固定策略/未知）、原始指令及结构化目标、目标部位/参考系/单位/停止条件、选择依据、预期响应、替代指令、下一观察门与父事件。

明确分开：当时可见的事实、当时记录的假设、执行后的解释。没有原始理由时标为未知；导入器或 GPT 不得事后编造当时推理。API 未执行的候选保留 proposal 状态，不能声称具有控制结果。

### 控制执行经验

每个控制事件用 instruction_id 关联编排事件，记录实际模式序列、接口字段、单位与参考系、源前缀、控制阶段、参数/增益/限幅、指令前身体与接触状态、期望变化、实测响应和耦合影响。低频策略输入与高频最终手指目标分别保留采样率和证据引用；不强行降成同一频率。

必须区分“参考目标”“decoder 输出”“最终关节目标/力矩”“实际身体运动”“物体响应”。例如指令向上不能直接标为手腕或物体向上。反向响应只有在预定义测量量、参考系、时间窗和超过噪声容差的条件下才能分类，否则标 unknown；同时保存实际位移、时延和其他影响。它是局部观测，不自动推断因果或全局控制符号。

同向不足、反向、过冲、饱和、无明显响应、成功跟踪、失稳等标签允许并存且指向具体量。容差来源与响应提取器版本必须记录；无法从历史日志计算时保留缺失，不能编造阈值。

### 结果与证据等级

分别保存 instruction_achieved、task_success、native_success、approved_alternative_success、safety_stop、execution_complete、replay_verified、training_ready；每个结论绑定验收版本和测量值。未知不是 false。不同验收不合并成一个成功率，按钮掌面标准与原生标准分别报告。

执行状态至少区分 completed、physical_failure、preflight_rejected、planning_rejected、interrupted、infrastructure_error、unknown。失败原因允许多项及未知，不强迫在“编排错/控制错”中二选一。指令实现与否使用独立测量，任务成功与否使用原任务验收。

来源关系包含 parent_attempt、candidate_id、shared_plan_id、checkpoint_source、inherited_prefix、replay_of、comparison_group、declared_changes。回溯仅新后缀是新的执行；继承前缀不当新证据。复验和 token 回放单独保存但不当独立策略成功样本。

摘要简述条件、指令、实际响应、结果、适用边界及关键证据。第一版由确定性模板生成，不需要外部 API。未来可增加有输入/输出哈希及模型版本的模型摘要，但不得修改结构化事实。经验等级区分单次观察、重复支持、受控比较、未验证假设；缺乏可比分母时不输出“大概率失败”的概率。

## 全任务导入与未来自动记录

先枚举现有实验索引及实际案例，形成全任务 inventory；至少覆盖已知 HUMANO 十任务和发现的其他任务，不以四任务白名单过滤。忽略环境、依赖、渲染输出等非实验子树，避免把重复报告当新尝试。

为 augmentation、workflow、通用 pipeline 与历史异构记录提供适配器。每个发现项都进入覆盖率账本：已完整导入、部分导入、待映射、非尝试、错误；未知格式保存最小来源记录和错误原因，不能静默丢失或推断成功。没有可引用证据的报告结论仅标 reported，不能升级为 verified。

未来生产者在决策和阶段结束后写本地事件，在最终退出/异常时提交结果；经验导入使用持久化事件和幂等队列，独立于 200Hz 物理循环。崩溃通过下一次对账恢复；没有终态证据不得猜测失败原因。写入问题必须在任务记录中可见且可重试，不改变物理控制或把成功改成失败。为每条生产路线建立适配覆盖测试，区分“支持全任务 schema”与“所有生产者已自动接入”。

原始请求响应可能含敏感字段；只收录允许字段和清理后的证据片段，不复制认证配置、请求头或环境变量。原始文件哈希可存，检索工具不得以任意路径读取整个工作区。源文件丢失/哈希改变时标记证据失效，默认不用于可执行参数建议。

## GPT 检索接口与边界

建议提供 query_experience 和 get_experience 两个只读工具；第一版使用 SQLite 元数据筛选＋全文检索，辅以结构化状态/几何距离排序。中文采用可验证的分词或字符 n-gram，不假定默认英文分词可用；具体实现由开发者选择。嵌入检索不是第一版依赖，后续通过检索质量评估再决定。

请求包含 kind（编排/控制/两者）、任务、阶段、机器人/控制接口、当前观测、失败征兆、可用控制、数据集快照和结果预算。控制参数建议要求机器人与接口/模式兼容；版本不一致仅在显式验证的兼容表下复用，否则作为不兼容参考单列。未知条件不等价于兼容。

编排类允许跨任务检索相似接触/支撑问题，但必须明确差异；跨任务案例不自动提供可执行关节参数。返回少量成功和失败案例，包含相似性、差异、证据等级、原始指标与引用。按来源家族/共享前缀限制重复条目，不能用多个回放挤占结果。

默认最多 6 条、总内容约 4000 tokens（可配置），完整动作数组和视频不直接塞入上下文。每条摘要有字符上限，并记录截断；实际模型请求另记真实用量。无兼容案例时返回“无适用证据”，允许原规划继续，禁止放宽约束伪装匹配。命中结果只供决策参考，不能覆盖执行器校验、预算、安全门或原验收。

接入点：初始规划前、失败后的下一次规划前。固定候选队列模式只在生成队列前检索；若改成逐次反思须显式声明新的研究条件。每个尝试冻结有效数据集快照和查询结果；当前尝试尚未完成的后验信息不进入自己的规划上下文。

## 如何验证收益

第一层不运行物理：模式校验、幂等导入、全任务覆盖账本、路径迁移、缺失证据处理、指令与执行关联、反向响应分类边界、回放去重、查询条件隔离、中文检索和上下文预算。

人工审阅一组有成功、控制不足、反向/耦合响应、基础设施错误的样本。没有反向实测样本时使用合成数据测试分类器，并明确不算机器人经验。检查导入摘要是否忠实、检索是否返回适用与有帮助的案例。

第二层另行制定并冻结物理实验协议：无检索与有检索两组使用相同任务/场景、模型设置、控制权限、验收、候选与时间预算政策；候选内容允许因检索而改变，这是处理效应。记录 API 用量、检索/规划/仿真用时、独立回放、成功率和重复无效动作次数。预先规定任务内重复数、配对方式与统计不确定性，不通过只挑成功任务宣称收益。

以源示范、初态/场景、共享候选及其后代形成来源组，再划分检索库与评估集；同组复验、回溯与摘要不得跨集合。主对照使用冻结数据集，评估新结果可入库但对两组不可检索。若研究在线积累，另设协议，明确何时可见、两组信息权限和预算，不与冻结对照混算。

## 交付与不在本轮范围

设计通过后，实施计划应交付：版本化 schema、全任务 inventory/导入器、规范记录与摘要、可重建索引、查询工具、持久事件与生产者接入、覆盖与检索审计报告。先建立可追溯数据与只读检索，再接规划器；任何“已覆盖所有任务”声明必须附 inventory 分母与未完成项。

本轮不修改导航/抓取控制器、不实现尚未完成的 historical_contact_reuse、不更改验收、不启动物理成功率试验、不自动发布到外部服务。模型摘要、向量库和训练导出是后续可选扩展。实际物理评估需独立冻结实验合同，并遵循既有运行环境与实验命名规则。
