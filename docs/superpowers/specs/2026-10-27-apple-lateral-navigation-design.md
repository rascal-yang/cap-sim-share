# 苹果横向泛化：从成功 replay 提取支撑条件并联合规划操作

状态：方案 2 和本设计已获用户批准（“开始实现”）；独立实施审阅未发现重大缺项。本文不是物理成功记录。

## 用户意图与边界

在 cap-sim-api-augmentation 开发 harness 数据增广，先改善苹果横向位置泛化，再扩展其他任务。用户指出此前苹果可能放得太远，因此本轮只沿桌沿横移苹果，保持距桌沿的深度、初始高度、桌面和机器人初态不变。

用户已选择“从修复成功的 replay 提取操作条件，再联合筛选站位和操作参考”。以下搜索网格、实施分层和预算是实现建议，不冒充用户指定参数。

目标是根据新位置确定是否需要移动、移到什么支撑位置，以及达到什么实测条件后开始操作。导航结束与抓取成功分开验收。不会把一条示范的成功扩大为整个横向区间可达，也不以放宽碰撞、接触或成功门限取得通过。

## 方案选择

1. 只补充站位提取、继续整体重定位旧操作轨迹：改动小，无法充分适应手臂和腰部调整。
2. 提取支撑与操作关系、联合筛选站位及重新求解操作参考：用户已选择；先检查无需移动的可行性，再考虑有限站位候选。
3. 同时重做行走和操作控制器：本轮不选；现有停车问题需独立验证，避免扩大研究变量。

## 坐标、基线和输入

建立桌面坐标系：z 为重力反向；n 为朝桌内的水平法向；t 为桌沿水平切向。当前冻结场景 n=世界 +X、t=世界 +Y，必须从绑定的桌子几何/朝向核验，不能拿球形苹果的任意 yaw 定义横向。

所有横移量相对上述修复成功源的苹果初始位置：p_new=p_source+delta_y*t。深度 n·p、高度、苹果姿态和桌子保持不变；机器人初始 qpos/qvel、SONIC 历史与物理不因变体改变。输出同时记录世界坐标、相对成功源的偏移和相对原始数据集的偏移，禁止把成功源已有 X 偏移算成新变量。苹果需保持在桌面有效支撑范围内，否则为场景无效。

输入包括冻结 scene/model、完整实测状态和时间、原始控制命令（尤其手指）、任务/阶段绑定、成功结果及验收口径、接触策略、运行时和源文件哈希。物理状态行、policy tick、手指命令行采用显式映射；缺少证据返回 needs_annotation。生成参考单独存储，其 qvel 不冒充源实测速度，不能借用源 success 字段认证新参考。

## 提取可操作支撑配置

从已验证成功、合手前的操作入口向前寻找连续稳定支撑窗口，并检查从窗口到入口没有重新迈步。保留多个满足条件的候选窗口及拒绝原因，不选“整条轨迹最长静止段”。第一版可使用显式阶段绑定，不要求自动语义识别。

每个窗口保存：左右脚完整位姿、脚间距离/朝向、支撑几何、root 和骨盆相对双脚的关系、相对桌沿和苹果的位置、全身实际姿态，以及到后续关键阶段的状态行映射。保留分布和变化范围，避免用单个中值掩盖姿态改变。

操作约束覆盖张手接近、首次接触、合手、抬起和最终验收时刻。保留腕朝向、手指命令和手—物体关系；追踪闲置左手与桌面的距离。几何支撑与真实足底力分别标记；旧记录缺力数据时仅作为候选先验，运行时仍要求实测支撑。

## 站位与操作的联合筛选

搜索变量是双脚支撑配置，root 作为导航适配目标和操作参考的一部分，不能把 root 位置恒定作为操作成功条件。

候选依次包括当前实测双脚、原成功双脚，以及沿 t 平移的成功双脚模板。第一版固定模板朝向和距桌沿深度，仅搜索横向平移；默认建议 2.5 cm 网格，覆盖原支撑位置到随苹果平移的支撑位置，并在两端各扩展一格，去重后最多 21 个候选。左右脚相对关系不从单条示范推断自由变化范围。对当前双脚配置单独求解，不能仅把它的 root 套入历史腿姿。

每个候选在规划副本中生成新的完整操作参考：

1. 将右手操作目标按苹果横移映射，保持源腕朝向、阶段与手指命令对应；左手目标沿用适合该候选的身体相对参考，并单独避碰。
2. 将双脚约束在候选支撑配置；保留源骨盆随操作变化的形状作为姿态偏好，允许有界全身 IK 调整以满足脚、腕、关节范围和几何约束。不得机械固定 pelvis，也不得沿用原腿关节后宣称新脚位已约束。
3. 先检查关键阶段，再检查全部生成状态及段间插值，包括腕朝向/位置残差、足部残差、关节与参考速度、身体/双手/物体碰撞和接触阶段。仅关键帧 IK 通过不能作为完成。
4. 检查到该候选的导航路径和从到达姿态到操作入口的连续桥接。关节插值只能用于双足已支撑情况下的姿态桥接，不能伪装成移动脚位的步行。

所有求解器迭代、候选数、几何采样和总耗时有显式上限；数值容差/速度上限沿用已有已声明配置或在新配置中标明依据。超时返回 inconclusive/planning_budget_exhausted，与确实观察到的碰撞、不可满足残差分开。接触豁免仅来自阶段绑定，禁止自动豁免所有历史碰撞。

排序：通过硬约束且满足声明的最低余量后，优先不移动，其次更短路径、更大操作余量、更小先验偏离，最后稳定 ID。最低余量并非本设计凭示范认定的能力；须记录具体计算和阈值。输出每候选的失败阶段、数值残差与碰撞对。

## 代码边界和证据产物

复用 Python/NumPy/SciPy/MuJoCo；FK/IK 在 no_physics 规划副本中运行。扩展 `workflow/navigation` 的 archive/prior/planner/native；提取、约束求解和参考包各自分层，文件名由实现者决定。增加显式苹果横向配置版本，旧通用重定位模式和四任务入口保持可用。

生成参考包必须包含 qpos/reference time、命令手指序列、source_row 映射、阶段/接触门、候选双脚配置、源证据哈希、生成代码/配置哈希、逐段验证和 dynamic_execution_verified=false。源 measured trajectory 与生成 reference 使用不同字段、不同哈希，不制造带“成功”含义的新 replay。

必须一起修改 `integration.validate_bound_plan`、`measured_handoff`、`WholeBodyOperation` 的消费接口：新模式执行已验证的生成参考，不能在执行器中再次调用旧 transformed 把原动作整体平移；旧模式继续走原路径。计划绑定源和生成物两套证据、精确索引范围和手指时间映射，发现内容变化直接拒绝。

## 导航、停车和操作交接

继续使用显式 SONIC1.0 CPU mode1 控制、实测反馈和现有有界路线控制；运行时版本为 TensorRT10.13.0.35/ORT1.23.2，由 cap-sim/scripts/humano_python.sh 启动并保存 loaded-session provider/model checks。新路径原 token 前缀为 0；没有 mode0、重置状态、写入 live qpos 或 token 兜底。源成功记录的 346 步原 token 前缀和 preencoder 姿态反馈修正另行审计；开发结果不能描述成相对该源只有横向位置一个变化。在新方法内部的横向条件间保持执行接口一致。

物理上可达某个 root 并不保证指定落脚。停车后读实际双脚、root/qvel、物体和接触，从实际支撑配置对操作段重新求解和检查一次；不强行把身体恢复成示范。生成参考更新为执行派生物，保留原计划、实测输入和哈希，不改写冻结合同；合同提前声明这条有界派生流程、代码、配置和预算。操作开始前若连续低速/支撑/桥接/几何检查未通过，返回 handoff_not_ready，第一版修正次数为 0。

在线求解期间不得无限暂停物理后继续用过期状态：只能在有界、明确记录的规划暂停点求解；恢复前重新读取状态和验证适用性，暂停墙钟与仿真时间分别计量。控制循环内不能隐藏长时间优化。

已有停车证据不合格且与横向移动不匹配，不能借用或放宽其范围。先验证横向行走和停车的控制响应；缺匹配证据允许离线计划，执行返回 needs_calibration。静态无需移动的分支仍需支撑和操作桥接检查，不能伪造停车标定。

## 验证顺序与接受标准

1. 离线提取回归：源原位能还原支撑与阶段；骨盆移动不误判迈步；入口已闭手、未成功源、缺命令、脚离地等明确拒绝；原始文件哈希保持不变。
2. 离线横向网格：0、±5、±10、±15、±20 cm；只改苹果横向坐标。报告有效场景数、规划完成/拒绝/预算耗尽、是否需要移动、候选脚位、全段残差/碰撞、耗时。规划通过不能当作抓取成功。
3. 集成回归：新参考确实进入执行器；实测落脚偏离引发重新求解或拒绝；源/生成包/场景篡改、索引偏移、手指提前合拢、物体位移、缺停车证据均不能绕过门禁。
4. 物理开发分批：冻结合同时先验证原位，再尝试 ±5 cm；通过后扩展 ±10 cm，再考虑 ±15/±20 cm。一次批次最多三个有证据支持的尝试，失败先记录与诊断，禁止把全网格无条件排队。需要导航的场景先完成匹配的横向停车校验；其记录独立于抓取尝试。
5. 每个有效尝试报告导航到位、实测交接、接触、抬起、原生验收和端到端结果；保持源验收口径。同步记录真实时间、规划/仿真/渲染/总墙钟；缺测填未知。每次启动前完整冻结 experiment.json；视频浅层中文副本、hash 和源索引依工作区规范。

本轮为用户指定的横向开发验证，不是历史 IK/mode0 对 SONIC 的正式方法对比。下一次正式对比仍按工作区要求使用历史最近十个位置/桌高条件，匹配初态、物理、时序、手命令和验收，声明原 token 前缀及所有不可消除的差异。

## 研究解释与实施者可决定的细节

本轮从 replay 学到的是操作支撑关系与进入条件，导航路径根据新场景生成；操作段访问原动作并做 IK 重定向，明确记录 trajectory_retargeting、planner_access_to_original_actions=true，不据此宣称完整技能生成或策略迁移。

实现者可决定模块拆分、缓存、确定性求解器和测试夹具组织，并在配置/审计中固定求解与采样预算；不能更改坐标含义、实验变量、手指/阶段映射、成功口径、运行时接口、前缀政策或把几何通过升级为物理成功。任何无法在预算内实现的约束返回明确能力边界。
